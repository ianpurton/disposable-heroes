# First mission: reference, behavior and acceptance

## Original data reference

Reference input is OpenFodder/data revision `3feb494023e4d008f8d7b548167e3e9ad31bad29`, AmigaTheOne/mapm1. The development tool decodes four 16×16 bitplanes per BLK tile and the 12-bit RGB palette, following `Source/Amiga/Graphics_Amiga.cpp` (`Map_Tile_Draw`, `DecodePalette`) in OpenFodder/openfodder revision `0df22170a1c125be31a8aaef97fb190793c29d1b`.

Run `python3 scripts/reference_tiles.py`. Compare `tmp/original-first-mission.png`, the numbered `tmp/jungle-tiles.png`, and `tmp/battlefield.png`. Every tile used by the mission is explicitly cataloged in `assets/catalogs/jungle.json`. The large impassable regions are leafy jungle formations. They are not rock. The renderer groups BHT cells into bounded foliage patches; tests prove coverage without closing gaps or changing collision.

Original graphics stay in ignored data/ and are used for development reference. Shipped 3D foliage and ground textures are generated by `scripts/generate_jungle.py`.

## Controls and movement

Left click selects/moves, held right click fires, both buttons use selected explosives. Split/rejoin and group controls retain the existing behavior. Navigation uses deterministic eight-neighbor A* on the two-pixel BHT grid, with two source pixels of soldier clearance, no diagonal corner cutting, direct movement when clear and simplified waypoints. Blocked/unreachable orders stop at the nearest reachable position; a wholly rejected order shows a red marker. Followers use the leader's trail; when the leader dies, they continue their own destination. Destruction rebuilds navigation and existing routes.

A* routing and two-pixel clearance are deliberate usability choices, not claims about the original algorithm. Their compatibility with specific original narrow passages should be reviewed during host playtests.

## Combat tuning and fidelity limits

Named settings live in `CombatTuning`, in original source-pixel units: land speed 48/s, water speed 20/s; rifle/grenade/rocket ranges 180/110/260; rifle/rocket speeds 340/220; player rifle interval 0.16s. Enemy reaction, cadence and aim error derive from the phase's aggression range. Defaults remain deterministic and fast, with lethal bullets.

Enemies use terrain/building visibility, explicit reacting/engaging/searching/idle states and 1.2 seconds of last-seen memory. Projectile collision and visibility use the same blocked terrain and intact building footprint. Visual plants never add collision. Terrain blocking sight is an explicit modern interpretation and needs comparison with the Amiga game, especially for foliage that originally permitted gunfire.

These values and AI are provisional. No cycle-accurate or footage-measured equivalence is claimed. Remaining fidelity work is a side-by-side Amiga playthrough comparing travel time, follow spacing, shot intervals, detection, terrain movement and first-mission difficulty.

## Visual and input checks

All test images belong in ./tmp. Offscreen `--smoke-test` captures the overview; `--combat-preview` runs deterministic movement/fire and captures tmp/combat.png. Native window clicks must additionally verify deployment, group selection, movement, firing, retry and camera tracking. Host audio mixing remains a separate check because this container has no audio output device.

## Performance

`cargo run --release -- --fresh --benchmark --benchmark-seconds 20` measures a scripted first-mission scenario at 1920×1080, with a three-second warmup and no desktop compositor or vsync. Results go to tmp/benchmark.json. Report p50/p95/p99 frame times, peak entities/mesh instances, and supported render diagnostic spans. Mesh instances are not draw calls; draw-call data is marked unavailable when the backend does not expose it. Review a release build on the user's Linux host before claiming a 60 fps target has been reached.
